# ai-service

FastAPI service implementing the **hybrid recommender** required by the
SoAD thesis Ch.3:

> `final_score = w1·LSTM + w2·Graph + w3·RAG`

| Component | Tech | Source |
|---|---|---|
| **LSTM** | PyTorch (`nn.LSTM(input_dim=N, hidden_dim=64) → nn.Linear`) | `app/lstm/` |
| **Knowledge Graph** | Neo4j 5 + Bolt driver | `app/graph/` |
| **RAG** | FAISS `IndexFlatIP` + `sentence-transformers/all-MiniLM-L6-v2` (384d) | `app/rag/` |
| **Hybrid scoring** | min-max normalised, weighted sum | `app/hybrid.py` |
| **API** | FastAPI 0.115 + uvicorn | `main.py`, `app/routes/` |

## Endpoints

| Method | Path | Description |
|---|---|---|
| `GET`  | `/health` | Service + model status |
| `GET`  | `/recommend?user_id=&query=&top_k=` | Hybrid recommendation list |
| `POST` | `/chatbot` `{ "query": "...", "top_k": 5 }` | RAG chatbot — retrieve + (optional LLM) generate |

## Quickstart (via the existing docker-compose)

```bash
# Build everything
docker-compose up --build -d

# Wait ~60s on first run — sentence-transformers downloads the embedding
# model (~80 MB) on the first request, and the LSTM trains on synthetic
# sequences derived from product-service + order-service data.

# Sanity check
curl http://localhost:8014/health
curl "http://localhost:8014/recommend?user_id=1&top_k=5"
curl -X POST http://localhost:8014/chatbot \
  -H "Content-Type: application/json" \
  -d '{"query": "tôi cần laptop gaming dưới 40 triệu", "top_k": 5}'

# Through the Nginx gateway (single entry point)
curl "http://localhost:8080/api/ai/recommend?user_id=1"
curl -X POST http://localhost:8080/api/ai/chatbot \
  -H "Content-Type: application/json" \
  -d '{"query":"sách lập trình Python","top_k":3}'
```

## Knowledge-graph topology

After the seed step the graph contains:

```
(:User {id})
  -[:BOUGHT  {first_order_id, count}]→ (:Product)
  -[:VIEWED]→                          (:Product)

(:Product {id, name, price, product_type, category_id})
  -[:IN_CATEGORY]→ (:Category {id})
  -[:SIMILAR {weight, source}]→ (:Product)
        # source = "co_purchase"  (weight ≥ 1.0, accumulates per pair)
        # source = "category"     (weight 0.3, intra-category edges)
```

Recommendation Cypher (see `app/graph/queries.py`):

```cypher
MATCH (u:User {id: $user_id})-[b:BOUGHT]->(p:Product)-[s:SIMILAR]->(rec:Product)
WHERE NOT (u)-[:BOUGHT]->(rec)
WITH rec, sum(coalesce(b.count,1) * coalesce(s.weight,1.0)) AS score
RETURN rec.id, rec.name, score ORDER BY score DESC LIMIT $top_k
```

You can browse the graph at <http://localhost:7474> (login: `neo4j` / `bookstore-secret`).

## Training data pipeline

The AI service trains on the **Amazon Books Reviews** dataset (Kaggle:
`mohamedbakhet/amazon-books-reviews`). The pipeline is offline — the
container only *loads* pretrained weights at startup, it does not train.

Committed artefacts under `ai-service/data/` (all generated by `make preprocess`,
except `lstm_weights.pt` which comes from `make train-ai`):

| File | Schema | Rows | Consumed by |
|---|---|---|---|
| `product_corpus.jsonl` | `{product_id, name, type, category_id, category, price, brand_or_author, description, keywords[]}` | 500 | FAISS + Neo4j (metadata source-of-truth) |
| `user_behavior.csv` | `user_id, product_id, action, timestamp` (action ∈ view/add_to_cart/purchase) | ~ hundreds of k | LSTM (sliding-window sequences) |
| `graph_triples.csv` | `source_type, source_id, edge_type, target_type, target_id, weight` (edge ∈ IN_CATEGORY/BOUGHT/VIEWED/SIMILAR) | varies | Neo4j seed |
| `lstm_weights.pt` | PyTorch checkpoint (state_dict + vocab maps) | — | LSTM inference (loaded at startup) |
| `seed_data_books.sql` | product-service catalogue + demo cart/order/review | 500 books + 12 | `data/seed_all.sh` → `product_db` |
| `user_id_map.json` | Amazon `User_id` → internal int | — | reference |

The raw ~1 GB Kaggle download lands in `ai-service/data/raw/` (gitignored).

### One-time setup (developer machine)

```bash
pip install -r requirements-dev.txt            # kagglehub + pandas
export KAGGLE_USERNAME=...  KAGGLE_KEY=...      # https://www.kaggle.com/settings/account
make data-pipeline                             # download → preprocess → train-ai
```

To retrain after refreshing the dataset:

```bash
make train-ai
git add ai-service/data/lstm_weights.pt && git commit -m "chore: retrain LSTM"
```

### Mirror strategy (why end-to-end still works)

A real Kaggle catalogue has 100k+ books, but the rest of the system
(cart/order/payment) references a small set of `product_id`s. So preprocess
selects a **500-book subset** (100 per internal category, books with ≥ 50
reviews) and writes `seed_data_books.sql` that mirrors exactly those 500 books
(IDs 1–500) into product-service, with electronics/fashion shifted to 501–512.
Recommendations therefore resolve to real, browsable catalogue items.

### Known trade-offs

- Book content is English (from Amazon); the storefront UI labels stay
  Vietnamese. Acceptable for the thesis demo, which highlights AI quality.
- Amazon `categories` → 5 internal categories is heuristic (see
  `scripts/category_mapping.py`); unmatched books fall back to category 1.
- LSTM is not benchmarked on a holdout set; graph SIMILAR edges are heuristic.
